How speculative decoding works

The draft model proposes several future tokens cheaply, and the target model verifies them in parallel. The final emitted text is the longest accepted prefix, plus a corrected token if a mismatch occurs.

The system outputs the accepted prefix, then the target model supplies a corrected token at the rejection point, and the next speculative round begins.

Core idea: instead of asking the target model for one token at a time, speculative decoding uses a cheap drafter to guess several tokens ahead and lets the expensive target model verify them in one go.

Why speculative decoding can be faster

Autoregressive decoding normally makes the target model wait for its own previous token before starting the next step. A drafter breaks that dependency on the expensive path: it guesses a block first, then the target scores all draft positions together with causal attention.

It is not automatically γ times faster. The drafter has a cost, rejected suffix work is wasted, and larger verification batches consume memory. Speedup is best when drafts are cheap, acceptance is high, and the hardware executes the wider verifier batch much faster than the equivalent sequence of target-model calls.

EAGLE / EAGLE-3

sequential / tree drafter target hidden features

Uses target-model hidden states from already verified tokens. EAGLE-3 fuses low, middle, and high target-layer features, then directly predicts token logits through a lightweight decoder and the target LM head.

l, m, h ∈ ℝᵏ
[l; m; h] ∈ ℝ³ᵏ → FC → g ∈ ℝk
draft output a ∈ ℝk → LM head → ℝ|V|

DFlash

parallel drafter KV injection

Extracts selected target-layer hidden states from the verified prefix, projects them into the draft hidden space, and injects them as extra keys/values into every draft layer.

H(li) ∈ ℝn×d
concat m layers: ℝⁿˣᵐᵈ
Wc: ℝd×md → Hctx ∈ ℝn×d
draft slots: ℝγˣᵈ → logits ℝγˣ|V|

DFlash 2

parallel backbone path selector + local conv

Keeps DFlash's one-pass block drafter, adds two-tap dynamic convolutions to strengthen local features, then selects a coherent path through each position's top candidates using lightweight adjacent-pair scores.

top-k candidates per position · k = 16 reported
pair score Sₜ(a,b) = Uₜ(b) + local compatibility
parallel scores → cheap sequential path walk

DSpark

parallel + tiny sequential confidence scheduler

Reuses the DFlash-like context-injected parallel backbone, then adds a lightweight Markov or RNN head so each sampled slot can depend on previously sampled draft tokens.

parallel: hk ∈ ℝd, Uk ∈ ℝ|V|
Markov: W1[xk−1] ∈ ℝr, W2 ∈ ℝr×|V|
bias Bk ∈ ℝ|V|, final logits Uₖ+Bₖ

MTP

sequential drafter target-attached

Combines a target representation with the current token embedding, projects the pair into a lightweight causal block, and recursively uses that block to draft several future tokens.

target feature ht ∈ ℝD, token e(xt) ∈ ℝd
zt = Wp[ht; e(xt)] ∈ ℝd
causal draft block → logits ℝ|V|

DFlash 2: choose a coherent path without rerunning the backbone

Plain DFlash predicts every draft position in parallel and normally keeps the top-1 token at each slot. DFlash 2, announced by Inco AI in August 2026, preserves that parallel backbone but addresses two failure modes: independently chosen tokens may not fit together, and candidate quality tends to decay near the end of a block.

1 · Keep candidate lists

Instead of immediately collapsing each position to one token, retain its top candidates. The reported selector uses the top 16, where recall is much higher than top-1 recall in Inco's Qwen3-4B GSM8K example.

2 · Score local transitions

A 256-dimensional, context-gated bilinear term scores how well candidate b follows candidate a. All adjacent candidate pairs at all positions are scored together; no extra Transformer backbone or LM-head pass is needed.

3 · Repair suffix decay

Two-tap dynamic depthwise convolutions mix each draft representation with its predecessor at every layer. This carries short-range information across the block while all positions remain parallel.

DFlash hidden states dynamic local conv top-16 per slot parallel pair scores short path walk target verify

How it differs: EAGLE and MTP build draft tokens autoregressively. DSpark keeps a parallel backbone but sequentially adjusts a full-vocabulary distribution and can schedule a shorter verification prefix. DFlash 2 computes backbone features, local convolutions, and pair scores in parallel; only the inexpensive walk through precomputed candidate scores is sequential. Target verification—and lossless rejection sampling when sampling—still determines the final output.

MTP: a target-attached autoregressive drafter

“Multi-token prediction” can mean a training objective with several future-token losses. In speculative decoding, the trained MTP module is reused as a small drafter. Despite the name, the Gemma/GLM-style drafter does not predict the whole block independently in one pass: it preserves the causal chain and drafts left-to-right.

target ht + e(xt) concat + project zt ∈ ℝd lightweight causal block xt+1 recurse γ times
Gemma 4 · separate assistant checkpoint

Four draft layers reuse the target's work

Gemma 4's target-specific assistant shares input embeddings, concatenates the target's last-layer activation with the sampled token embedding, and down-projects the result into its own hidden size. Its four-layer text backbone also reuses target KV states, avoiding a separate draft prefill.

target last-layer activations + sampled-token embeddings
shared input embedding table · shared target KV state
E2B/E4B: clustered vocabulary lookup reduces output cost
GLM 5.2 · NEXTN layer inside the checkpoint

One physical module, reused across draft depths

GLM's MTP family shares the embedding and output head with the target and recursively applies a lightweight Transformer module. GLM 5.2's published checkpoint declares one NEXTN layer; its model card reports that the improved MTP design increases accepted draft length by up to 20% over its preceding design.

target/previous-depth representation + shifted token embedding
one checkpoint NEXTN layer · shared embedding/output head
sequential proposals, then ordinary target verification
Closest relative on this page: EAGLE. Both preserve a causal draft chain and condition on target features. EAGLE-3 deliberately fuses several target layers and can expand a verification tree; MTP is usually a target-specific module packaged or trained with the base model. DFlash instead predicts all γ slots in parallel, while DSpark adds only a tiny sequential correction head after its parallel backbone.

Compact algorithm sketches with shapes

EAGLE-3-style

target pass over verified prefix:
  li, mi, hi ∈ ℝk
  gᵢ = FC([lᵢ;mᵢ;hᵢ]) ∈ ℝᵏ

draft step:
  input: g for verified tokens
         + e(anchor) or previous a as proxy
  decoder output a ∈ ℝk
  logits = LM_head(a) ∈ ℝ|V|
  sample token
  feed a back for deeper draft steps

DFlash

target context:
  H^(l₁)...H(lm) ∈ ℝn×d
  Hctx = RMSNorm(Wc concat(H)) ∈ ℝⁿˣᵈ

draft input:
  [E(anchor), E(MASK) ...] ∈ ℝγˣᵈ

each draft layer:
  K,V = concat(project(Hctx), project(Hd))
  output logits ∈ ℝγ×|V|

DFlash 2

parallel DFlash 2 backbone:
  local_conv(x)ₜ = kₜ,₀⊙xₜ + kₜ,₁⊙xₜ₋₁
  Uₜ, hₜ = draft(masked_block)
  Cₜ = top_k(Uₜ, 16)

parallel adjacent-pair scores:
  Sₜ(a,b) = Uₜ(b)
    + ⟨A(a) ⊙ H(hₜ), B(b)⟩

short sequential walk:
  start from last verified token
  choose a path through C₁...Cγ
  verify selected path with target

DSpark

parallel backbone:
  hk ∈ ℝd, Uk ∈ ℝ|V|

Markov head:
  q = W1[xk−1] ∈ ℝr
  Bₖ = q W2 ∈ ℝ|V|
  pₖ = softmax(Uₖ + Bₖ)

confidence:
  cₖ = sigmoid(wᵀ[hₖ; q])
  scheduler chooses prefix length ℓ

MTP-style

first draft depth:
  h⁰ = target final representation

for draft depth j = 1...γ:
  zʲ = Wp([hʲ⁻¹; e(xʲ⁻¹)]) ∈ ℝᵈ
  hʲ = draft_block(zʲ) ∈ ℝᵈ
  logitsʲ = shared_head(hʲ) ∈ ℝ|V|
  sample xʲ

verify [x¹...xᵞ] with target

Open-source LLMs using these methods in 2026

“Uses” means that an open draft checkpoint is available for the target model (EAGLE-3, DFlash, DFlash 2, and DSpark), or that the released model checkpoint includes a native draft module (MTP). Availability does not mean that speculative decoding is enabled by default in every inference stack.

DFlash Qwen3 4B, 8B, and 14B; Gemma 4 12B. A separately trained block-diffusion drafter paired with each target checkpoint.
DFlash 2 Qwen3.8-27B and Muse Glimmer 30B. A separately trained DFlash-compatible drafter with local dynamic convolutions and top-k path selection.
DSpark Qwen3 4B, 8B, and 14B; Gemma 4 12B. A separately trained semi-autoregressive drafter plus confidence-based verification scheduling.
MTP drafter Gemma 4, DeepSeek-V3, and GLM 5.2. A native target-attached module shipped with, or alongside, the released model weights and reused for drafting.
Direction in 2026: speculative decoding is moving from stand-alone, serial draft models toward target-co-designed MTP modules and parallel or semi-autoregressive drafters. DFlash 2 shows a second direction: improve coherence by selecting among parallel candidates rather than autoregressively recomputing full logits.
